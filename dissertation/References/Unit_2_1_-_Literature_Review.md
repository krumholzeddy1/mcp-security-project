# Unit 2.1 — Literature Review

*Detecting Tool-Poisoning Attacks in MCP Agentic Systems Using Machine-Learning-Based Anomaly Detection*

Agentic systems built on large language models depend on a boundary between instructions and data that the underlying architecture does not enforce. Perez and Ribeiro (2022) were among the first to demonstrate this systematically, showing that a model given no formal way to distinguish developer instructions from user-supplied text can be redirected simply by asking it to disregard its prior instructions. Greshake et al. (2023) extended this finding from direct to indirect injection, arguing that any application integrating an LLM with external content — documents, web pages, retrieved records — inherits the same vulnerability, since the model cannot tell an instruction that arrived through legitimate data from one that arrived through legitimate command. Their taxonomy of resulting harms, including data theft and unauthorised actions, has remained the reference point for later work in this area.

Subsequent research has traced this same conflation into agentic, tool-using systems specifically. Zhan et al. (2024) introduced a benchmark for tool-integrated LLM agents and found that agents calling external tools were reliably manipulated through content encountered mid-task, extending the indirect-injection problem from passive retrieval into active, autonomous tool use. This shift — from an LLM reading untrusted content to an LLM acting on untrusted content through tool calls — is the point at which the general prompt-injection literature connects directly to the protocol-level concerns this project addresses.

Model Context Protocol (MCP), as the current standard for that tool-calling layer, has become the specific focus of a small but fast-growing 2025 literature. Hou et al. (2025) characterise MCP's architecture as one in which trust is assumed between each layer — user, model, client, server — but never re-verified once a session is under way, which they identify as the structural source of the protocol's attack surface. Building on this, Radosevich and Halloran (2025) and Invariant Labs (2025) independently documented working tool-poisoning exploits, in which an attacker-controlled server embeds instruction-like content inside ordinarily descriptive fields — a tool's name, description, or schema — so that the model interprets metadata as command. Willison (2025) identifies a related but distinct pattern: tools that pass initial inspection honestly and only rewrite their own descriptions after being trusted and connected, a delayed attack he terms a "rug pull." Where the injection literature above establishes that models cannot distinguish instruction from data in general, this MCP-specific body of work shows the same failure recurring at the level of tool metadata rather than message content.

The defences proposed against this class of attack are, so far, uniformly structured around a single moment: registration. Bhatt et al. (2025) propose OAuth-enhanced tool definitions and policy-based access control to constrain what a registered tool is permitted to do, and note this as an improvement over unscoped trust — but their model, like the schema-validation and manual-review practices Hou et al. (2025) and Radosevich and Halloran (2025) describe, evaluates a tool once, when it first connects. None of these approaches re-examines a tool's behaviour or description later in a session, which is precisely the condition Willison's (2025) rug-pull pattern is designed to exploit. This is a gap in mechanism, not merely in implementation effort: a defence that only ever checks at registration cannot, by construction, notice something that changes afterward.

A separate and older body of literature offers a plausible route to closing that gap. Outside the LLM context, intrusion detection research has long distinguished signature-based approaches, which match observed behaviour against a known-bad database, from anomaly-based approaches, which use statistical or machine-learning methods to flag deviation from an established behavioural baseline (Ahmed et al., 2025). The consistent finding in that literature is that signature-based methods are efficient against known patterns but structurally blind to novel or time-delayed ones, while anomaly-based methods trade some efficiency for the ability to catch exactly the kind of deviation a one-shot check cannot. This distinction maps directly onto the MCP problem: current tool-poisoning defences are signature- and registration-based in character, and the rug-pull literature identifies a delayed-deviation attack of the type anomaly-based methods were developed to catch in other domains.

No study identified in this review has yet applied that anomaly-detection paradigm to MCP tool-call metadata specifically. The existing MCP security literature documents the attack classes and proposes registration-time mitigations; the broader security literature establishes that behavioural anomaly detection can catch what one-shot checks miss; but the two bodies of work have not yet been connected. This is the gap the present project addresses: whether machine-learning-based anomaly detection, applied to tool-call metadata and description-change patterns rather than to payload content alone, can detect tool-poisoning and rug-pull attacks that registration-time schema validation is structurally unable to catch.
